# AI workflows

TalentSync calls Google Gemini only from the Express backend. The configured model is `gemini-3.6-flash`, and every workflow requests structured JSON that is validated with Zod before use. `GEMINI_API_KEY` is a backend-only secret and must never be exposed to the React application.

## Resume parsing

1. A candidate uploads a validated PDF to the private `resume-files` bucket.
2. The API retrieves the candidate-owned object.
3. `pdf-parse` extracts bounded text on the backend.
4. Gemini returns profile fields, skills, experience, education, certifications, and a summary that the backend validates against the expected schema.
5. The repository persists the analysis and updates normalized candidate profile data.

Route: `POST /api/v1/resume/parse`

## Candidate summary

A recruiter can request a concise professional summary for an application they are authorized to view. Candidate content is delimited as untrusted data and cannot override system instructions.

Route: `POST /api/v1/ai/candidate-summary`

Input: `{ "applicationId": "<uuid>" }`

## Match score

The match workflow returns:

- Score from 0 to 100
- Matching skills
- Missing skills
- Recommendation
- Evidence-based rationale

Candidates pass a `jobId` for a transient self-assessment. Recruiters pass an `applicationId`; that result is stored with the application for later review.

Recruiter-side analysis prefers the completed parsed-data snapshot tied to the application’s submitted `resume_path`, so later profile edits do not silently change the evidence. The current profile is used only when no valid completed snapshot exists.

Route: `POST /api/v1/ai/match-score`

## Resume feedback

Structured feedback covers ATS readiness, grammar, skills, projects, formatting, and achievements. Access is application-scoped and recruiter-only.

Route: `POST /api/v1/ai/resume-feedback`

## Reliability and privacy

- Zod validates input and model output.
- Gemini Interactions API requests use `store: false`, which disables conversation-state storage. Paid-service prompts and responses may still be logged for a limited period for abuse monitoring unless Google approves Zero Data Retention for the project.
- Long resume/job inputs are bounded before prompting.
- Model calls share one `GEMINI_TIMEOUT_MS` budget across bounded retries; the default is 30 seconds and the browser allows an additional transport margin.
- Production startup fails fast when `GEMINI_API_KEY` is missing or `GEMINI_SERVICE_TIER` is not `paid`; development can still run non-AI routes without a key.
- Provider failures are normalized into the API error envelope.
- Secrets and raw prompt content are not sent to the browser.
- TalentSync is intended only for users who are at least 18, and registration states that account-level eligibility requirement.
- Resume upload shows a non-blocking disclosure describing backend Gemini processing. The application does not collect, manufacture, or enforce a per-upload consent receipt; legacy nullable receipt fields remain only for historical rows.
- Google instructs developers not to send personal, sensitive, or confidential information to unpaid Gemini services. All candidate-data workflows fail closed unless the runtime declares a billing-enabled paid service.
- Unpaid access is limited to synthetic development checks containing no real personal or confidential data. Quota and rate-limit failures remain normalized.
- AI output assists hiring decisions and must not autonomously reject, select, or materially disadvantage a candidate without human review.
